# AGENTS.md — LIGHT SHADOW project map

Fast orientation for humans and AI agents. Verify cheaply; never re-derive from the tree.

## Identity

- **Game:** LIGHT SHADOW — first-person educational horror (no combat, no gore).
  Knowledge powers the flashlight: answer real questions → Bright Idea Meter → stronger light.
- **Engine:** Unity **6000.4.0f1**, URP 17.4, `Assembly-CSharp`. Windows (KB/M) + Android 10+ (touch).
- **Scene flow:** `00_Bootstrap → 01_MainMenu → 02_School → 03_Ending` (ending = 3D dawn set + study recap).
- **Docs:** `LightShadow_Project_Document.md` (vision, §2.4 cut list superseded by premium-pass brief —
  see `Docs/DECISIONS.md` D5), `README.md`, `AI_DEV_LOG.md` (mandatory AI-use log, doc §8.3),
  `Docs/` (AUDIT/ROADMAP/DECISIONS/PROGRESS/CHANGELOG/PERFORMANCE/ASSET_LICENSES/Story).

## Hard rules

1. **Never hand-edit `.unity`/`.prefab` YAML.** Scenes/prefabs are generated by the `SceneBuilder*.cs`
   partials (`Assets/_Project/Scripts/Tools/Editor/`). Change the builder → rebuild scenes.
2. All tuning lives in `GameConfig.asset` (`Assets/_Project/Data/GameConfig.asset`) — no magic numbers.
3. Naming: `Mat_` `SM_`/`SK_` `T_` `Q_[Cat]_[NNN]` `SFX_/MUS_/AMB_` (doc §6.7). English, no spaces.
4. Third-party assets live read-only under `Assets/ThirdParty/<pack>/`; copy-and-adjust into
   `_Project/`. Log every download in `Docs/ASSET_LICENSES.md` before use.
5. Question `factSource` stays `NEEDS-FACT-CHECK` unless a human verified it. Never claim review.
6. Log every AI-assisted change as a fragment file `AI_DEV_LOG.d/<YYYYMMDD>-<slug>.md`
   (one per PR; template at the top of `AI_DEV_LOG.md`). Never append to the shared tail.
7. Commit .meta files next to assets; never commit `Library/ Temp/ Logs/ Builds/ UserSettings/`.
8. No jumping; walk/sprint/crouch only. The Shadow is "enemy behaviour" (FSM), never "AI".
9. **PR-only:** never push directly to `main`. All changes land through pull requests that
   are green and conflict-free (see Git workflow below).

## Git workflow (PR-only — every agent, no exceptions)

`main` is the protected source of truth. The only way in is a pull request.

**PR size rule (owner instruction, 2026-11-27 23:00): every PR must carry at least 5,000 lines of
valuable code change, and more is better.** Bundle related features, fixes, tests and tooling
into one PR to reach it. Never pad: no generated filler, no reformatting churn, no duplicated
code, no dead code and no stretching a change to hit the number. If a real piece of work is
smaller, bundle it with the next piece of real work on the same branch instead of opening a
small PR. Count lines of source, tests, builders and hand-written docs; do not count
binary assets, generated files or lockfiles. State the line count and what it contains in the PR body.

1. Branch off latest `origin/main`: `git fetch origin && git switch -c <type>/<topic> origin/main`
   — prefixes `feat/` `fix/` `docs/` `perf/` `chore/`.
2. Commit granularly with conventional messages (`fix(loading): …`); `.meta` files always
   committed next to their assets (rule 7).
3. Open the PR early: `gh pr create --fill`; extend the body with what changed and how it
   was verified.
4. Before merging, verify — all three must hold:
   - Working tree clean and everything pushed.
   - Tests pass for the touched area (see Verification below): runtime/editor scripts →
     `ValidateBatch` (grep `RESULT: PASS`); scene/prefab layout changed → `BuildAllBatch`
     first, then `ValidateBatch`; docs/workflow-only → the CI fast-checks are the gate.
     Every PR additionally runs the `build` workflow (Windows player + one APK per Android
     ABI, parallel, Library-cached) — those checks must be green before merge.
   - PR is `MERGEABLE` (no conflicts with `origin/main`); if not, `git switch <branch> &&
     git merge origin/main`, resolve, re-push.
5. **While CI runs, keep working on the project** — poll `gh pr checks --watch` between
   tasks; never idle while waiting.
6. Merge only when every GitHub check is green AND the PR is mergeable:
   `gh pr merge --squash --delete-branch`, then `git fetch origin && git switch main &&
   git pull --ff-only`. If a check is red, fix on the same branch and push — never bypass.

## Code quality bar (a merge blocker, same as failing tests)

- Fits the existing architecture: config-driven (rule 2), event-driven (`GameEvents`),
  builder-generated scenes (rule 1). A new singleton needs a justification in the PR body.
- Compiles warning-clean; no `Debug.Log` spam, no commented-out code, no dead files.
- Runtime code never references `UnityEditor` outside `#if UNITY_EDITOR`; editor-only code
  lives in `Scripts/Tools/Editor/`.
- All user-facing strings go through `Localization` with EN and AR both filled.
- Every runtime tunable is a `GameConfig` field — no literals (rule 2).
- Keep PRs small and reviewable; no drive-by refactors mixed into feature work.

## Verification (run from repo root; one Unity instance at a time)

```bash
U="C:/Program Files/Unity/Hub/Editor/6000.4.0f1/Editor/Unity.exe"
"$U" -batchmode -quit -nographics -projectPath . -executeMethod LightShadow.Tools.SceneBuilder.ValidateBatch -logFile Logs/validate.log      # content validation (RESULT: PASS)
"$U" -batchmode -quit -nographics -projectPath . -executeMethod LightShadow.Tools.SceneBuilder.BuildAllBatch -logFile Logs/build.log        # rebuild scenes/prefabs after layout changes
"$U" -batchmode -quit -nographics -projectPath . -executeMethod LightShadow.Tools.SceneBuilder.BuildWindowsBatch -logFile Logs/win.log      # Builds/Windows/LightShadow.exe
"$U" -batchmode -quit -nographics -projectPath . -executeMethod LightShadow.Tools.SceneBuilder.BuildAndroidBatch -logFile Logs/android.log  # universal ARM64 APK → Builds/Android/LightShadow.apk
"$U" -batchmode -quit -nographics -projectPath . -executeMethod LightShadow.Tools.SceneBuilder.BuildAndroidArm64Batch -logFile Logs/android-arm64.log  # per-ABI APK → Builds/Android/arm64-v8a/
"$U" -batchmode -quit -nographics -projectPath . -executeMethod LightShadow.Tools.SceneBuilder.BuildAndroidArmV7Batch -logFile Logs/android-armv7.log  # per-ABI APK → Builds/Android/armeabi-v7a/
"$U" -batchmode -quit -nographics -projectPath . -executeMethod LightShadow.Tools.BuildProfileTool.EnsureBatch -logFile Logs/profiles.log   # repair build profiles if boot aborts
```

No x86_64 Android build: Unity 6000.4 deprecates that architecture (Magic Leap legacy)
and `BuildPlayer` throws when it is targeted.

Grep logs for `RESULT:|error CS|Exception` — never read a full Unity log. Exit code 0 = success
(player builds throw and exit 1 on a failed `BuildPlayer` since the CI/CD pass).
If boot aborts with "Failed to read the specified build profile": run `BuildProfileTool.EnsureBatch`;
if it persists, delete `Library/EditorUserBuildSettings.asset` (machine-local) and rerun.
