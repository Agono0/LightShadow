## 1. Current architecture (what exists today)

### 1.1 The code mixer — `Assets/_Project/Scripts/Audio/VolumeCategories.cs`

- Static class, no scene object. Bootstraps via `[RuntimeInitializeOnLoadMethod(AfterSceneLoad)]`
  (`Bootstrap()`, VolumeCategories.cs:55–68): loads 5 PlayerPrefs levels (`ls_vol_master`,
  `ls_vol_music`, `ls_vol_ambience`, `ls_vol_sfx`, `ls_vol_ui`, ints 0–10, default 8,
  VolumeCategories.cs:29–34) and subscribes `SceneManager.sceneLoaded` to re-scan.
- `enum Category { Master, Music, Ambience, Sfx, Ui }` (VolumeCategories.cs:25).
- **Registration:** two paths — explicit `Register(source, category, baseVolume)` (line 103)
  and the per-scene name-convention scan `ScanActiveScene()` (line 126) +
  `CategoryFromName()` (line 139): `MUS_/Music*`→Music, `AMB_/Ambien*`→Ambience,
  `UI*`→Ui, `SFX_`→Sfx, **everything unmatched → Sfx**.
- **Volume math** (`ApplyTo`, line 166–171):
  `source.volume = baseVolume * CategoryVolume01(category) * MasterVolume01` — a pure
  linear per-source multiply, re-applied on every slider move (`ApplyAll`, line 152) and
  every scene load. Zero per-frame cost, but per-source: anything not registered never
  hears the sliders.
- **Settings UI:** `SettingsPanelController` rows 17–21 (`VolumeMasterRow`…`VolumeUiRow`,
  SettingsPanelController.cs:46–50) call `VolumeCategories.SetLevel(...)` for the − / +
  buttons (lines 210–214, 241–245) and read back via `GetLevel` (labels at 352–356,
  400–402). The rows themselves are generated by `SceneBuilderStory.ExtendSettingsPanel`
  (page-B keys `"Master volume"… "UI volume"`, SceneBuilderStory.cs:854–857). **No other
  UI code touches audio.** `GameSettings` has no volume fields — all audio prefs live in
  `VolumeCategories` (`GameSettings.cs` verified: only graphics/input/narrator).

### 1.3 Known gaps that motivate the change

1. Per-source scaling means every source must be *registered* to hear the sliders; late-spawned
   sources are invisible until the next scene load, and `PlayClipAtPoint` never is.
2. `AdaptiveMusic` and `VolumeCategories` share ownership of `.volume` by convention, not by design.
3. No buses: nothing can duck or muffle a whole class of sound (the brief §8.3 snapshot
   choreography is impossible in the current design).
4. `GameEvents` has **no chase event** — `EnemyBehaviour.EnterState` (EnemyBehaviour.cs:254–284)
   raises nothing; `ShadowAudio` polls `CurrentState` per frame. Snapshot driving needs a state
   source (fixed in §4.3).

## 2. Target architecture — the mixer asset and its builder

### 2.1 Asset

- `Assets/_Project/Audio/Mixers/M_Main.mixer` (new folder `Assets/_Project/Audio/Mixers/`).
- Group tree — categories carry **user volume**, duck children carry **snapshot ducking**:

```
Master                (user Master slider; + Lowpass effect, snapshot-owned cutoff)
├── Music             (user Music slider)
│   └── MusicDuck     (snapshot-owned gain, default 0 dB)
├── Ambience
│   └── AmbienceDuck
├── SFX
│   └── SfxDuck
├── Voice             (empty this pass — see §6.3)
│   └── VoiceDuck
├── Shadow
│   └── ShadowDuck
└── UI
    └── UiDuck
```

- Six snapshots as sub-assets (exact names in §3). `startSnapshot = Snapshot_Explore`.
- Sources keep routing to the **category** group (Music, Ambience, …), never to the duck
  children; signal flows `category → duck → Master`.

### 2.2 Who builds it — new editor tool `Assets/_Project/Scripts/Tools/Editor/AudioMixerTool.cs`

Consistent with `AudioImportTool.cs` (same folder, same batch/menu style, `EnsureFolder`
helper reused). The repo rule is "generate assets via editor tools, never hand-edit" — the
mixer is created through **Unity's own serialization pipeline** (AssetDatabase + the editor
mixer controller classes), not by writing YAML text.

**Batch entry:** `LightShadow.Tools.AudioMixerTool.EnsureBatch()` (menu
`LightShadow/Audio/7. Build Audio Mixer`, priority 26). `SceneBuilder.BuildAll()` calls
`AudioMixerTool.BuildMixer()` right after `AudioImportTool.ImportAll()` (insert at
SceneBuilder.cs:238 — the comment there already reads "The audio library must exist before
the Systems object is wired"; the mixer must exist before scenes are built for the same
reason). Idempotent: loads the existing asset when valid, rebuilds groups/snapshots only
when missing or mismatched.

**APIs (all verified in UnityCsReference; all internal → reached via reflection with

## 3. Snapshot set (exact names, values, rationale)

All group volumes in dB (Unity range −80…+20); low-pass cutoff in Hz. Values live in the
mixer asset (data, not code); transition times are runtime tunables → `GameConfig` (§4.5).
"User" rows (`MasterVol`…`UiVol`) are stored at **0 dB in every snapshot** — they are
script-owned via `SetFloat` (§4.4) so their snapshot values are inert; they are listed
only so the builder writes them explicitly.

### Snapshot_Explore  (`startSnapshot`, also menu/bootstrap state)

| Param | Value |
| --- | --- |
| all Duck groups | 0 dB |
| MasterLowpass | 22000 Hz (fully open) |
| all user params | 0 dB |

*Rationale (brief §8.3):* the neutral reference. Every other snapshot is a relative move
from this state, so Explore must be mathematically flat — no colouring of the school-at-night
bed, sliders feel 1:1.

### Snapshot_Stalk  (Shadow in Stalk)

| Param | Value |
| --- | --- |
| MusicDuck | −2 dB |
| AmbienceDuck | −3 dB |
| SfxDuck | −1 dB |
| VoiceDuck | 0 dB |
| ShadowDuck | +1.5 dB |
| UiDuck | 0 dB |
| MasterLowpass | 12000 Hz |

*Rationale (§8.3):* the stalk is "the horror beat" (doc 4.3) — dread without announcing
itself. A gentle air-loss (12 kHz) plus ambience receding and the Shadow's breathing
gaining 1.5 dB makes the room feel smaller while nothing snaps at the player.

### Snapshot_Chase  (Shadow in Chase)

| Param | Value |
| --- | --- |
| MusicDuck | 0 dB (pulse layer runs at full AdaptiveMusic envelope) |
| AmbienceDuck | −6 dB |
| SfxDuck | −2 dB |
| VoiceDuck | −6 dB |
| ShadowDuck | +2 dB |
| UiDuck | −6 dB |
| MasterLowpass | 20000 Hz |

*Rationale (§8.3):* panic needs the full spectrum — the muffle opens instead of closing.
The world gets out of the way (ambience −6), the Shadow pushes forward (+2, plus the
`ShadowAudio` proximity envelope), narration ducks under the chase. Transition is the
fastest in the set (0.15 s) because the visual catch cue (`ShadowAudio` stinger +
`PooledWhisperBurst`) must land with the audio.

### Snapshot_Hide  (player inside a `LitZone`)

| Param | Value |
| --- | --- |
| MusicDuck | −4 dB |
| AmbienceDuck | −4 dB |
| SfxDuck | −3 dB |
| VoiceDuck | 0 dB |
| ShadowDuck | −3 dB |
| UiDuck | 0 dB |
| MasterLowpass | **900 Hz** |

*Rationale (§8.3):* the specified "low-pass + music duck". 900 Hz is the strongest muffle
in the set — lit zones are the safe rooms, and the muffled world reads as "door closed,
chalk line claimed". ShadowDuck also drops (the Shadow genuinely cannot enter lit zones,
doc 4.3), so even its breathing recedes.

### Snapshot_MemoryFlash  (fragment / fuse story beat — transient overlay)

| Param | Value |
| --- | --- |
| MusicDuck | −4 dB (music keeps the emotion, yields to the voice) |
| AmbienceDuck | −15 dB |
| SfxDuck | −12 dB |
| VoiceDuck | **0 dB (untouched — this is its moment)** |
| ShadowDuck | −15 dB |
| UiDuck | −12 dB |
| MasterLowpass | 12000 Hz (mild dream-air; narration 300 Hz–4 kHz stays crisp) |

*Rationale (§8.3):* "duck all but Voice/Music". Drives on `GameEvents.FragmentCollected`
and `GameEvents.FuseRestored` — exactly the beats where `StoryTeller.Speak` narrates the
memory (KnowledgeFragment.cs:49, GameManager.cs:181). Duration `GameConfig.memoryFlashSeconds`
(6 s), then release back to the active state snapshot.

### Snapshot_Dawn  (dawn chase / ending set)

| Param | Value |
| --- | --- |
| MusicDuck | +1.5 dB |
| AmbienceDuck | 0 dB |
| SfxDuck | +1 dB |
| VoiceDuck | 0 dB |
| ShadowDuck | 0 dB (the Shadow is aggressive again in the dawn chase, doc Act III) |
| UiDuck | 0 dB |
| MasterLowpass | 22000 Hz |

*Rationale (§8.3):* the dawn is the warm, open climax (DawnRiser + 3D ending set) — the
mix **lifts** (+1.5 music, +1 sfx) instead of muffling; slowest transition (2.5 s) for the
swell. Drives on `GameEvents.DawnStarted` and holds through `EscapeStarted`.

## 4. Runtime bridge

### 4.1 Chosen topology for user volumes — **Option A: exposed params driven by VolumeCategories; snapshots own only duck children + Master low-pass**

The two candidate designs from the brief were:

- **(A)** category groups expose their Volume as exposed params, `VolumeCategories` writes
  them via `AudioMixer.SetFloat`; snapshots duck **separate child groups** and the Master low-pass.
- **(B)** `VolumeCategories` writes child groups while snapshots live on a parent bus above them.

**A is chosen.** Deciding fact — Unity semantics (AudioMixer.bindings.cs:170, quoted):
*"Once you call SetFloat… **mixer snapshots will no longer control the exposed parameter**."*
So the split must guarantee `SetFloat` and snapshots never target the same parameter:

- User sliders → `SetFloat` on the seven user params (`MusicVol`…) — **script-owned forever**,
  transitions never fight the sliders. A slider move mid-chase applies instantly and survives
  every snapshot transition.
- Snapshots → `MusicDuckVol`… + `MasterLowpass` — **never SetFloat'ed** (asserted in the
  controller), so transitions animate them.

B fails `Snapshot_MemoryFlash` ("duck all but Voice/Music"): a single parent bus above the
user-volume groups can only duck everything together; per-category ducking needs the child
layer that A already provides. A additionally keeps the mixer authoritative for every source
routed to a group (including future/spawned sources), which fixes the registration gaps of
§1.2 by construction.

Linear→dB map for the 0–10 sliders (identical PlayerPrefs keys, so player settings survive):
`dB = level <= 0 ? −80f : 20f * Log10(level / 10f)` — level 10 → 0 dB, 5 → ≈ −6 dB, 0 → −80 dB
(effectively silent, same as the old linear 0).

### 4.2 New runtime component — `Assets/_Project/Scripts/Audio/AudioSnapshotController.cs`

One component, two jobs (replaces the need for a separate `AudioMixerBootstrap`):

- **Wiring** (like `AudioLibraryBootstrap.library`): `public AudioMixer mixer;`
  `Awake()` → idempotent `VolumeCategories.SetMixer(mixer)` + `DontDestroyOnLoad(gameObject)`
  (PerformanceManager/AdaptiveMusic singleton pattern).
- **Snapshot driver**: holds `persistent` (Explore/Stalk/Chase/Dawn) and a transient
  `overlay` (Hide / MemoryFlash with expiry). `Update()` polls `LitZone.PlayerInLitZone`
  (LitZone.cs:24 — static, no event exists; polling a bool is free). Applies
  `overlay ?? persistent` via `mixer.FindSnapshot(name).TransitionTo(seconds)`.
  **Never** calls `SetFloat` on duck/lowpass params (guard + one-time assert in editor).
- Builder attaches it (idempotent, `GetComponent == null` guard like SceneBuilderStory.cs:532)
  to: the **00_Bootstrap** bootstrap object (so the mixer is active process-wide before the
  menu; the field wired by the builder), and the **school `Systems`** object (direct-play
  from the school scene). `VolumeCategories.SetMixer` is idempotent, so both are safe.

### 4.3 Event driving — one new GameEvent + existing ones

`GameEvents` header explicitly allows additions ("Add new events freely, never rename",
GameEvents.cs:11). Add:

```csharp
// The Shadow changed FSM state. Payload: (int)LightShadow.Enemy.EnemyBehaviour.State
// (Patrol 0, Stalk 1, Chase 2, Repelled 3). Raised from EnemyBehaviour.EnterState.
public static event Action<int> EnemyStateChanged;
public static void RaiseEnemyStateChanged(int state) { EnemyStateChanged?.Invoke(state); }
```

(`int` payload keeps `Core` free of a dependency on the `Enemy` namespace.)

`EnemyBehaviour.EnterState` (EnemyBehaviour.cs:254) raises it right after `state = next;`
(line 258). This covers **every** FSM transition in one place: Patrol→Stalk (line 189),
Stalk→Chase (211), Stalk→Patrol (217), Chase→Stalk/Patrol (240), Repelled→Stalk (249),
and `ResetToPatrol` after a catch (EnemyBehaviour.cs:307–314) — no per-transition edits.

Snapshot mapping in `AudioSnapshotController`:

| Trigger | Target | Transition |
| --- | --- | --- |
| `EnemyStateChanged(Patrol)` | Snapshot_Explore | 0.75 s |
| `EnemyStateChanged(Stalk)` or `(Repelled)` | Snapshot_Stalk | 0.5 s |
| `EnemyStateChanged(Chase)` | Snapshot_Chase | 0.15 s |
| leaving Chase (previous == Chase) | any | 0.6 s (release) |
| `LitZone.PlayerInLitZone` true/false | Snapshot_Hide ↔ back | 0.8 s in / 0.5 s out |
| `GameEvents.FragmentCollected` / `FuseRestored` | Snapshot_MemoryFlash overlay, expires after `memoryFlashSeconds` | 0.35 s in / 1.2 s out |
| `GameEvents.DawnStarted` (then hold through `EscapeStarted`) | Snapshot_Dawn | 2.5 s |
| `GameEvents.PlayerCaught` | no change — the catch fade + `ResetToPatrol` restore Explore naturally | — |

Subscriptions: `OnEnable`/`OnDisable` pairs for `EnemyStateChanged`, `DawnStarted`,
`EscapeStarted`, `FragmentCollected`, `FuseRestored` (exact existing events, GameEvents.cs:15–39).

### 4.4 `VolumeCategories` — exact code touch-points (`Assets/_Project/Scripts/Audio/VolumeCategories.cs`)

1. **Enum** (line 25): append `Voice = 5, Shadow = 6` (append-only — PlayerPrefs indices of
   the existing five stay stable). No new settings rows this pass (§4.6); defaults 8 = 0 dB.
2. **PrefKeys** (lines 29–32): append `"ls_vol_voice"`, `"ls_vol_shadow"`; `levels` array
   (line 46) extended to 7 entries. `Bootstrap` loop (61–64) is already generic.
3. **Mixer handle** — new members:
   ```csharp
   static AudioMixer mixer;
   static readonly AudioMixerGroup[] groups = new AudioMixerGroup[7];
   public static bool MixerActive => mixer != null;
   public static void SetMixer(AudioMixer m)      // idempotent; resolves groups
   public static AudioMixerGroup GroupFor(Category c) => groups[(int)c];
   ```
   Group resolution: `mixer.FindMatchingGroups(name)` matches by sub-path, so pick the
   candidate whose **exact** `name` equals the group name (prevents `Music` matching
   `MusicDuck`); null-safe — an unresolved group leaves `GroupFor` null and the legacy
   path keeps working.
4. **`SetLevel`** (lines 79–90): after the PlayerPrefs write, call
   `ApplyMixerVolumes()` when `MixerActive`, else the existing `ApplyAll()`:
   ```csharp
   static void ApplyMixerVolumes() {
       mixer.SetFloat("MasterVol",   LevelToDb(levels[0])); // + per-category: MusicVol, AmbienceVol,
   }                                                        // SfxVol, VoiceVol, ShadowVol, UiVol
   ```
   `CategoryChanged` event unchanged (no subscribers today — kept for future UI).
5. **`ApplyTo`** (lines 166–171) — routing + one-line math change:
   ```csharp
   source.outputAudioMixerGroup = GroupFor(category);
   source.volume = MixerActive ? baseVolume
                               : baseVolume * CategoryVolume01(category) * MasterVolume01;
   ```
   `baseVolume` stays per-source (authored layer bases); category × master becomes the
   group gain. Same product as before for registered sources, so loudness is preserved.
6. **`ScanActiveScene` / `CategoryFromName`** (lines 126–148) — add component-based
   overrides **before** the name rules, fixing the §1.2 mis-categorizations:
   - `source.GetComponentInParent<LightShadow.Enemy.EnemyBehaviour>() != null` → `Category.Shadow`
     (covers `Breathing`, `TheShadow` one-shot, `ShadowAudio` growl/stinger);
   - `source.GetComponent<LightShadow.Core.AmbientDrone>() != null` → `Category.Ambience`;
   - name contains `"whisper"` → `Category.Shadow` (pooled whispers);
   - existing name rules unchanged; unmatched → Sfx (unchanged).
   Everything else (`MusicSource`, `AmbienceSource`, `SfxSource`, footsteps) routes through
   this existing scan with **no builder changes**.

  library → preset `Room` (dead, decay ≈ 0.6 s, Room −10000 mB); corridors → `StoneCorridor`
  (medium); hall/gym → `Auditorium` (long). Place from the existing shell-room bounds;
  no new systems.
- **Occlusion** — one `AudioOcclusionProbe` on `TheShadow` (added by
  `SceneBuilderPrefabs.BuildEnemyPrefab`): a single `Physics.Raycast` player→Shadow per frame
  (reuse the `EnemySight` LOS mask); when blocked, lerp an `AudioLowPassFilter` on
  `ShadowAudio.growlSource` 22000 → 8000 Hz and −6 dB volume (the §8.3 "raycast low-pass −6 dB").
  Only the Shadow's sources occlude this pass (that is the audibly important case).

**Why defer:** this PR already touches every source's routing path; reverb zones anchor to
shell-room geometry (which the art pass keeps reshaping) and reverb costs real CPU on the
Android tier — it needs its own `Docs/PERFORMANCE.md` measurement. Small, reviewable PRs are
a merge gate (code quality bar). Ship snapshots + routing first; reverb/occlusion as PR #2.

### 6.3 What breaks if Voice/Shadow sources bypass the mixer

- **Voice (`StoryTeller`):** verified — it plays **out-of-process** (SAPI COM on an STA thread,
  StoryTeller.cs:117–242; fallback PowerShell `System.Speech`, StoryTeller.cs:268–321) through
  the OS audio session. It **cannot** route to the Voice group; no code change can fix that
  without replacing the narration pipeline. Consequences today: narration ignores Master/Music
  slider context (it already did under D15 — no regression), and the VoiceDuck values are
  inert until the premium pass ships recorded VO clips (which will be AudioSources → Voice
  group). The Voice group is created empty now so the VO migration is a routing one-liner.
  (Optional future work, out of scope: SAPI `AudioOutputStream` → WAV → `AudioClip` played
  through a Voice-group source on a dedicated GameObject.)
- **Shadow sources:** if `Breathing`/`TheShadow`/`ShadowAudio` sources stayed unrouted they
  would (a) ignore the sliders unless name-matched (today they land in Sfx by default —
  audible but wrong bus), and (b) concretely break the snapshot choreography: `Snapshot_MemoryFlash`
  ducks everything **except** Voice/Music by −12…−15 dB — an unrouted Shadow growl keeps its
  full volume and pokes over the narrated memory beat; `Snapshot_Hide`'s −3 dB ShadowDuck and
  the `Snapshot_Chase` +2 dB push would not apply, so the world muffles while the Shadow sits
  at authored loudness. The §4.5 explicit routing + the §4.4.6 scan override both close this.
