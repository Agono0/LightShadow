# Abdelraouf — code, gameplay and 3D packages (LightShadow)

This extends `Docs/ABDELRAOUF_WORK_PLAN.md`. Package 1 there (native-Arabic
review) stays as is. Packages C1-C6 below are sizable feature work, chosen so
they grow the game without touching anything the instinct-side chain or the
bro-side asset streams are editing.

Rules are unchanged (`Docs/EXTERNAL_AGENT_BRIEF.md`): you OPEN pull requests
(from your fork), only the owner's side merges, never push to `main`, claim
each package in `Docs/WORK_CLAIMS.md` first, one `AI_DEV_LOG.d/<date>-<slug>.md`
fragment per PR, no deploys/releases/spending, no changes to
`ProjectSettings/`, `Packages/`, `.github/`. Say what you verified vs
estimated. Nothing in this repo has been tested on a real device; CI green is
not correctness.

## 1. Your lane (conflict-free)

Everything you add lives under one root that no other stream touches:

```
Assets/_Project/Contrib/Abdelraouf/
  Scripts/        C# runtime code (+ hand-authored .meta each, fresh GUID)
  Editor/         your Editor-only code (scene/prefab builders for your content)
  Models/         your 3D assets (.glb/.fbx) + .meta
  Materials/ Textures/ Prefabs/ Audio/ Data/   your content
Docs/contrib/abdelraouf/    your notes, asset register, design docs
```

- Namespace: `LightShadow.Contrib.Abdelraouf.<Feature>`.
- No `.asmdef`: the project is one assembly (`Assembly-CSharp`); an asmdef
  would cut you off from `LightShadow.Core`. Keep your code in your folders.
- Do not edit existing files under `Assets/_Project/Scripts/**`,
  `Models/ Materials/ Textures/ Prefabs/ Audio/ Art/` (the shared folders),
  `Assets/_Project/Tests/Editor/` or `Data/Questions/`. Use the extension
  points in section 2 instead. If you truly need a change in a shared file,
  write it in your PR description as a request; the owner's side applies it.
- Never hand-edit `.unity` or `.prefab` YAML. Build prefabs/scenes from code
  in your `Editor/` folder (see section 3).
- Each new `.cs` needs a `.meta` with a GUID not used anywhere in the repo
  (grep before you commit; CI `fast-checks` verifies meta pairing).
- 3D: glTF/GLB preferred (glTFast is installed), low-poly style per
  `Docs/STYLE_GUIDE.md`, CC0 or self-made only, every asset recorded in
  `Docs/contrib/abdelraouf/ASSET_REGISTER.md` (name, source, license, tris).
  Budget per prop: under 3k tris, one material, mobile-friendly textures
  (max 1024 px).

## 2. Integration contracts (existing APIs you may call, read-only)

These exist on `main` today. Treat them as stable; do not change them.

| Need | Use |
| --- | --- |
| Something the player aims at and presses E on | implement `LightShadow.Gameplay.IInteractable` (`Prompt`, `CanInteract`, `Interact(GameObject)`) |
| Localized text | `Localization.Tr("English sentence")`; the English is the key, add Arabic via your own table (see C6 note) and always ship both |
| Story/world events | subscribe to `GameEvents` (`FragmentCollected`, `FuseRestored`, `GatePowered`, `PlayerCaught`, `CheckpointReached`, `QuestionAnswered`, `DawnStarted`, `EscapeStarted`), unsubscribe in `OnDisable` |
| Items | `Inventory.Add/Has/Remove(string id)`, `Inventory.ItemAdded` |
| Save/load | `SaveSystem.SaveCaptured` / `SaveApplied` events. Today `SaveData` has no generic blob for you. Instinct-side PR **H1** adds `contribJson` (string, per feature key) so you can persist state; until H1 lands, keep your state in memory and mark persistence TODO |
| Audio | `AudioManager.Instance.PlaySfx/PlaySfxAt/PlayVoice`; new clips go in your own `Audio/` folder and are referenced from your code or `Data/`; do not edit `AudioLibrary.asset` |
| Pooling | `ObjectPool` in `Scripts/Systems` |

Contracts the owner's side will add so you are not blocked (tracked as H1-H2,
each its own small PR from us):

- **H1 save blob**: `SaveData.contribJson` keyed by feature id.
- **H2 scene hook**: a `ILevelContribution` interface in `Scripts/Tools/Editor`
  that `SceneBuilder.BuildAll()` discovers by reflection. Implement it in your
  `Contrib/Abdelraouf/Editor/` folder; `Build(LevelContext ctx)`
  is called after the base scene is generated, with `ctx` giving the spawn
  point, the root transform for dynamic objects, and the layer constants.
  Dynamic objects MUST use layer 0 (not `LevelLayer`), or they seal the
  NavMesh bake (known trap, fixed in #58).

Until H2 lands, build and test your content in your own additive scene
generated by your Editor code (`Assets/_Project/Contrib/Abdelraouf/Scenes/`
is yours, generated by an Editor menu item and committed only if CI
regenerates it; otherwise commit just the builder code).

## 3. Packages

Order is a suggestion; pick one, claim it, finish it, open the PR, then take
the next. Each is sized for a few focused PRs.

### C1 — Lore journal (code + UI + content)
- **Scope:** collectible notes the player picks up (new `JournalNote`
  implementing `IInteractable`), a `JournalBook` that stores found notes, and
  a runtime-built UI screen listing them (pause-menu style, built in code
  with uGUI, EN+AR). Write 12 short notes in `Data/` (JSON or
  ScriptableObjects) that deepen the school story without contradicting
  `Docs/Story/`; mark them draft for narrative review.
- **Contracts:** `IInteractable`, `Localization.Tr`, `GameEvents`,
  persistence via H1.
- **Done when:** notes can be picked up in your test scene, the journal lists
  them in both languages, nothing in shared folders changed.

### C2 — Hint system (code + UI)
- **Scope:** `HintService` that offers progressive hints (nudge, clue, answer)
  for the current objective after a configurable idle time or on a button.
  Hint text is data-driven per puzzle id (`Data/Hints/*.json`, EN+AR); hint
  use is counted for the end-of-run summary (expose the count, do not edit
  `RunResults`).
- **Contracts:** subscribe to `GameEvents`; read puzzle ids from
  `Docs/PUZZLES.md`; no edits to `PuzzleManager`.
- **Done when:** with a stub puzzle id the service raises the three hint
  levels in order, with cooldowns, and a small test scene shows them.

### C3 — Sound caption system (accessibility feature)
- **Scope:** on-screen captions for sound-only cues (footsteps near, whisper,
  door slam, power hum), directly closing the gap in Yusuf's accessibility
  review (`Docs/reviews/accessibility-2026-11-27.md`, finding 1). A
  `CaptionService` with `Raise(string englishKey, Vector3 worldPos)` and a
  directional indicator UI (left/right/behind arrows), EN+AR, with an
  on/off setting stored via a small `PlayerPrefs` key of your own.
- **Contracts:** call sites in shared code are ours; you ship the service and
  a documented one-line API. Open an issue-style request in your PR so the
  owner's side wires the calls (or use `AudioManager` events if you can
  observe them without edits).
- **Done when:** service + UI work in your test scene with simulated cues.

### C4 — East Wing level module (3D + level design)
- **Scope:** a new explorable wing (library annex or basement) as a
  self-contained level module: a modular kit (floor, wall, doorway, stair,
  pillar, ceiling, 8-10 hero props: shelves, desks, lockers, boiler,
  banners) in `Models/`, an Editor builder that assembles the layout from
  your kit and data (`Data/EastWing/layout.json`), light placement, and
  3-4 `JournalNote`/pickup spawn points (C1) and one key-style reward slot.
  Hook into the main scene through H2 when available.
- **Contracts:** dynamic objects on layer 0; no NavMesh sealing; lights use
  the project's warm/cold palette (`Docs/STYLE_GUIDE.md`); respect the
  mobile light budget (see `Docs/reviews/performance-review-2026-11-27.md`:
  few shadowed lights).
- **Done when:** the module builds from code, walkable in your test scene,
  asset register complete, tri/light counts reported honestly.

### C5 — Two new puzzle types (code + content)
- **Scope:** two new data-driven puzzles in your `Scripts/Puzzles/` folder
  that follow the pattern of the existing ones in
  `Assets/_Project/Scripts/Gameplay/Puzzles/` (read `PuzzleBase.cs` and one
  sample): suggested a pattern-memory panel and a pipe/wire routing grid.
  Each ships with EN+AR instructions, a solved event, and a reward hook that
  a level module can bind to (door key, fuse, battery).
- **Contracts:** inherit `PuzzleBase`; do not edit `PuzzleManager` (register
  via H2 or document the one-line registration for us).
- **Done when:** each puzzle is solvable and resettable in your test scene
  and its solve state serializes cleanly.

### C6 — Credits and epilogue scene (code + content)
- **Scope:** a credits/epilogue sequence the game can load after the ending:
  scrolling EN+AR credits driven by `Docs/CREDITS.md` data (parse at build
  time into `Data/Credits/credits.json`, do not edit the doc), a "what Nour
  learned" epilogue card sequence (draft text, narrative review needed), and
  a "return to menu" button. Arabic shaping: use `ArabicSupport` as the
  existing UI does and note anything that renders wrongly.
- **Contracts:** scene name constants live in `SceneNames.cs` (ours); request
  the entry in your PR, do not edit it.
- **Done when:** sequence plays end to end in your test scene; Arabic checked
  for shaping and RTL order (you are a native speaker, say what you verified).

inside your lane, `.meta` pairing and GUID uniqueness, CI green, honest

change is applied by us in a separate PR and linked. Merge order stays ours.
