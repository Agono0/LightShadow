# 2026-11-27 CI speed pass (user request 15:49)

Baseline (real runs, 2026-11-27): critical path is the two Android jobs, 996-2553 s each (cold Library: ~1990 s build step; warm: ~1290 s). test-editmode 527-613 s, windows 453-562 s. The "Free runner disk space" action cost 113-235 s in every job. Repo cache usage was 11.2 GB of the 10 GB quota (PR refs each saved 1.5-3 GB Library entries, evicting main's).

Changes
- Cache policy: PRs only restore; pushes to main save a fresh entry (key ends with run id, restore-keys prefix picks the newest). Library entries stop multiplying per PR ref and stop going stale.
- One shared Android Library cache for both ABIs (arm64 job saves it), instead of two ~3 GB entries.
- Disk cleanup: parallel `rm -rf` of the big preinstalled toolchains plus docker prune, with an automatic slow apt fallback if less than ~25 GB is free afterwards. Replaces jlumbroso/free-disk-space (apt purge was the slow part).
- Change detection gains a `player` output: PRs touching only `Assets/_Project/Tests/` (Editor-only, never shipped) still run test-editmode but skip the three player builds; required check names still report success.
- Gradle cache path pointed at the container HOME mapping (RUNNER_TEMP/_github_home/.gradle). Previously `~/.gradle` on the host, which the cache listing shows was never populated.
- validate.yml: cancel superseded PR runs.

Not changed (on purpose): all validation steps, the two-ABI split (separate APKs are required), required check names, secrets handling, action versions (bump bot PR #68 owns those).

Unverified until main runs: the Gradle path guess, the shared-Library-across-ABIs assumption, the 25 GB disk threshold on the Android image jobs. Timing results are reported from real runs in the PR thread, not estimated.
